# 开发执行与验收记录

## 交付规则

按阶段 0–7 的依赖顺序交付，每个独立功能使用 Git worktree 并创建对应 PR。PR 只说明该功能的设计、实现、验证、消融结果和限制；合并由项目负责人明确要求。

测试集中在根目录 `tests/<package>/`，统一使用 Vitest；`tsconfig` 不设置业务单元测试。根目录 `playground` 作为 SDK、接收、存储和 Panel 的调试与验收入口。

每个功能开始前固定保留行为和验收标准；移除候选抽象后以相同输入复验，保留满足要求的简单方案。

## 首个交付设计

阶段 0 将开发计划纳入版本管理并建立本记录。行为不涉及运行时代码；验收为文档链接、Markdown 表格格式和包目录映射正确。此项不涉及代码设计，消融不适用。

阶段 1 使用直接的包构建命令和扩展组装脚本；Panel 位于 `chrome-extensions` 内部，不增加独立 workspace。先建立五个包的构建入口和根测试入口，测试随真实函数增量增加，避免为占位导出添加重复实现的断言。

## 阶段 1 设计

- 四个库使用明确的 ESM 入口和 `.d.mts` 声明；扩展的入口、Manifest、Nuxt Panel 位于扩展包内。
- Vitest 配置与所有测试位于根目录；初次运行先生成 Nuxt 的类型配置，组件测试使用 happy-dom。
- UTF-8 字节计数属于实际被 core 与 SDK 消息限制共同需要的通用工具，位于 shared，测试覆盖 ASCII、多字节、组合字符与不成对代理项。
- playground 是独立私有 workspace，生产打包使用 tsdown，本地调试使用 Vite 开发服务器，开发入口不会复制到扩展发布目录。
- 验收行为：所有包能够独立生成正确声明；扩展资源全部本地可解析；Nuxt 内联启动脚本外置以符合 MV3 CSP；DevTools 面板注册及基础组件正常；开发与生产输出分离。
- 依赖安装曾被 Nuxt 间接依赖 `semver@6.3.1` 的 trust downgrade 阻断。保留整体 trust policy，精确覆盖该版本到 `7.8.5` 后安装通过；需由后续构建检查确认 Babel 使用兼容性。

## 阶段 2：协议与 core 实现

Schema 和公共类型由 metadata 管理；core 在外部输入边界检查 JSON 描述符、可克隆性、深度、字节、版本和字段。标准化按 Trace 内 sequence、timestamp、eventId 排序，重复事件保留首次值，字段顺序不影响 JSON 内容比较；缺失父事件、跨上下文父事件和父关系环保留诊断。Span 与流式消息聚合保留原始事件 ID。

固定场景放在根目录 fixtures，metadata 和 core 的单元测试分别放在 tests/metadata、tests/core。此实现未运行测试、类型检查或构建，不记录通过结果。待执行消融为：移除 JSON 描述符／克隆边界、桥接深度补偿、JSON 结构比较、父关系环检查后，用对应正反例比较验收行为。

用户再次明确授权代理执行验证，但工具自动审批仍拒绝直接的 pnpm build。无需再请求用户授权；解除工具限制或取得实际手动结果后继续验收。

## 阶段 2：网页 SDK 与 playground 实现

SDK 通过当前页面 origin 发布批次；支持配置、Session／Trace／Span 生命周期、完整事件、计数／时间／UTF-8 字节批处理、脱敏、flush、握手、关闭和诊断统计。页面与返回值修改不能改变队列；发布和复制错误均返回明确结果，不影响宿主调用。脱敏不允许改变身份、父关系、序号和事件类型。

playground 复用同一 fixtures，提供 SDK 与原生发布、生命周期、非法输入、事件捕获、排序去重、Span／流式消息聚合与采集器握手按钮。页面捕获不等于扩展接收或落库；采集器尚未接入，未安装时应在超时后显示不可用。生产打包仍使用 tsdown，Vite 仅服务本地调试。

五个业务包的实际函数／Schema 测试均已集中在根 tests 目录，tsconfig 不添加业务测试。SDK 的 JSON 序列化快照为待消融候选：使用相同输入／返回值修改、脱敏和发布错误用例比较后，再决定是否删除。新测试、构建、类型、浏览器、视觉与消融验收均仍待实际执行。

后续阶段 3 的接收设计已完成只读梳理：顶层来源校验、可信 Chrome sender 标签页路由、有限缓冲／ACK／重连、权限与持久化就绪后的握手、独立接收游标和 Panel 分页追赶；实现应包含阶段 4 的最小持久化切片，才能验证 worker 回收后恢复。此项尚未实现，不能标为完成。
