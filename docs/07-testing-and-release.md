# 阶段 7：测试、打包与发布

## 1. 阶段目标

建立覆盖协议、SDK、扩展通信、存储和 UI 主流程的验证体系，并产出可以安装和审查的 Chrome 扩展包。

第一版以可重复的本地安装包为必达目标；Chrome Web Store 上架作为同阶段的发布准备项，是否正式提交由项目负责人决定。

## 2. 测试分层

### 2.1 单元测试

| 包 | 必测内容 |
| --- | --- |
| `metadata` | Schema、类型推导、枚举和协议版本 |
| `core` | 校验组合、标准化、排序、去重、Span 聚合、版本迁移 |
| `sdk` | 数据发布、批处理、flush、禁用状态、脱敏 |
| `shared` | 纯工具函数和通用结果类型 |
| `chrome-extensions` | 内部消息、接收链路、存储适配、Panel 筛选、Timing 和布局状态 |

重点测试输入输出和边界，不编写只重复实现细节的测试。

### 2.2 组件测试

使用 Vue Test Utils + Vitest 验证：

- FilterBar 产生正确筛选条件；
- Table 正确展示状态和选中行；
- Details Panel 对不同事件显示对应字段；
- JSON Viewer 安全渲染字符串；
- 空状态和错误状态切换；
- props/emits 契约和键盘交互。

### 2.3 扩展集成测试

验证：

- content script 接收正确 channel；
- 非法消息被拒绝；
- Port 断线和重连；
- service worker 按 `tabId` 路由；
- IndexedDB 写入和查询；
- Panel 快照与增量衔接；
- 站点权限授予和撤销。

### 2.4 浏览器端到端测试

准备一个本地测试页面和稳定 Fixtures，至少覆盖：

1. 加载 unpacked extension；
2. 打开测试页面；
3. 为该页面授权；
4. 页面发送 Session、模型、工具和错误事件；
5. DevTools Panel 展示对应事件；
6. 筛选错误事件；
7. 打开详情并检查 Payload；
8. 关闭并重新打开 DevTools；
9. 导出 Session；
10. 清空并重新导入。

如果自动化框架无法稳定控制 DevTools 自定义 Panel，则保留可执行的集成测试，并为 Panel 部分维护严格的人工验收清单。

## 3. 执行任务

### 3.1 统一质量命令

在根目录形成稳定命令：

- `pnpm lint`；
- `pnpm typecheck`；
- `pnpm test`；
- `pnpm test:e2e`；
- `pnpm build`；
- `pnpm package:chrome`。

每条命令失败时必须返回非零退出码。CI 与本地使用同一套入口。

### 3.2 建立 CI

建议流水线顺序：

1. 安装锁定版本的 pnpm 和 Node.js；
2. 使用 frozen lockfile 安装依赖；
3. lint；
4. typecheck；
5. unit/component tests；
6. build；
7. extension integration tests；
8. 打包并上传构建产物；
9. 发布任务额外执行版本和 manifest 校验。

### 3.3 生产包检查

操作：

1. 只包含运行需要的 HTML、JS、CSS、图标和 manifest；
2. 不包含源码映射中的敏感本地路径；
3. 不包含测试 Fixture、开发服务器入口和未使用权限；
4. manifest 版本与包版本一致；
5. CSP 不允许远程代码执行；
6. 所有第三方许可证满足发布要求；
7. 压缩包解压后可以直接作为 unpacked extension 加载。

### 3.4 发布材料

准备：

- 产品名称和一句话描述；
- 详细功能说明；
- 权限用途说明；
- 隐私政策；
- 数据收集和本地存储说明；
- 图标和商店截图；
- 版本变更记录；
- 用户接入 SDK 的最小示例；
- 已知限制和问题反馈入口。

## 5. 最终验收步骤

1. 从全新工作目录执行依赖安装和构建；
2. 所有质量命令通过；
3. 生产扩展包能够成功加载；
4. 完整执行浏览器端到端验收流程；
5. 使用所有协议 Fixtures 检查 UI；
6. 检查 worker 重启、DevTools 重开和浏览器重启后的恢复；
7. 检查权限撤销、存储清理和扩展卸载行为；
8. 检查导出文件的脱敏结果；
9. 检查生产包权限、CSP 和远程资源；
10. 记录扩展版本、Git Commit、Chrome 版本和验收结论。

## 6. 发布阻断条件

出现下列任一情况不得发布：

- 合法事件被静默丢失且没有 dropped count；
- 不同标签页之间发生 Trace 数据串流；
- 未授权站点仍被监听；
- Payload 可以执行脚本或任意 HTML；
- 清空操作留下可查询的关联数据；
- 数据库升级会破坏旧数据且无恢复方式；
- 生产包包含远程执行代码；
- lint、typecheck、核心测试或生产构建失败。

## 7. 完成标准

- 本地和 CI 质量命令一致且通过；
- 有可复现的 unpacked extension 构建产物；
- 主流程具备自动化或明确的人工验收覆盖；
- 发布权限、隐私和数据说明完整；
- 每个发布包可以追溯到确定的版本和 Commit；
- 发布阻断项全部关闭或有明确的延期决策记录。
