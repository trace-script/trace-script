# 阶段 6：调试能力、性能与安全

## 1. 阶段目标

在核心链路和基础 UI 可用后，补齐真正用于问题定位的功能，并验证扩展在持续事件流和大数据量下保持稳定。

本阶段包括三部分：调试功能、性能优化和安全加固。

## 2. 调试功能任务

### 2.1 Timing 与瀑布图

操作：

1. 以当前 Trace 起点作为相对时间零点；
2. 将事件开始时间映射到横轴位置；
3. 将 `durationMs` 映射为宽度；
4. 对瞬时事件提供最小可点击宽度；
5. 区分运行中、成功、失败和取消；
6. Hover 显示准确的开始时间、结束时间和耗时；
7. 对缺失结束事件的 Span 显示“运行中”或“不完整”。

验收：同一 Fixture 中模型调用、工具调用和总 Trace 的相对位置与原始时间一致。

### 2.2 关联导航

操作：

1. 根据 `parentId` 建立父子关系；
2. 显示同一 Trace 内的上游和下游事件；
3. 从错误事件跳转到触发它的工具或模型调用；
4. 对孤立事件显示缺失关系提示；
5. 跳转后保持筛选条件并滚动到目标行。

验收：多 Agent handoff 和工具重试 Fixture 可以沿关系链完整导航。

### 2.3 导入导出与分享前准备

操作：

1. 支持导出当前 Session 或选定 Trace；
2. 导出前显示数据范围和敏感信息提示；
3. 支持应用脱敏规则后导出；
4. 导入文件进入独立的 imported Session；
5. 未知格式、损坏文件和超大文件有明确错误；
6. 第一版不实现远程分享链接，先保证本地文件可移植。

## 3. 性能任务

### 3.1 建立基准数据

使用固定生成器准备：

- 1,000 个事件的小型 Session；
- 10,000 个事件的中型 Session；
- 50,000 个事件的大型 Session；
- 每秒 50 个事件、持续 5 分钟的实时流；
- 包含 500 KB Payload 的大事件；
- 大量 `message.assistant.delta` 的流式场景。

记录测试设备、Chrome 版本、构建模式和采样方法，避免只记录孤立数字。

### 3.2 优化接收与存储

操作：

1. SDK 和 content script 使用批处理；
2. 单批设置事件数和字节数上限；
3. service worker 以事务批量写入；
4. 限制内存缓冲区，并记录 dropped count；
5. 面板隐藏时合并 UI 更新；
6. Payload 详情按需加载，不进入列表 DTO。

### 3.3 优化 Vue 列表

操作顺序：

1. 先测量普通表格性能；
2. 确认大列表成为瓶颈后再引入虚拟滚动；
3. 对大型事件数组使用浅层响应式状态；
4. 筛选和排序使用缓存的派生结果；
5. 避免在模板中重复执行过滤、排序和 JSON 格式化；
6. 避免为每个热路径单元格引入过度组件抽象；
7. 对 JSON Viewer 使用延迟展开。

### 3.4 初始性能验收目标

以下是 MVP 的初始目标，第一次真实数据测试后可以调整，但调整必须记录原因：

- 10,000 个事件的 Session 首次显示在 2 秒内完成；
- 滚动期间没有持续明显卡顿；
- 每秒 50 个事件持续 5 分钟，合法事件不被静默丢弃；
- Panel 不可见时不持续触发高频 Vue 重渲染；
- 普通筛选条件在 10,000 个事件规模下 300 毫秒内反馈；
- 清空一个 Session 后，关联 Trace 和 Event 不残留；
- 达到缓冲上限时显示明确的 dropped count。

## 4. 安全任务

### 4.1 输入边界

操作：

1. 网页消息视为不可信输入；
2. content script 做来源和轻量结构检查；
3. service worker 执行完整 Schema 校验；
4. 初始限制单事件序列化大小不超过 1 MB；
5. 初始限制单批不超过 100 个事件或 2 MB；
6. 超限事件拒绝并记录原因；
7. 所有错误文本和 Payload 使用安全文本渲染。

大小限制是默认保护值，后续可通过设置调整，但不得无限制关闭。

### 4.2 权限与隔离

操作：

1. 使用最小 Manifest 权限；
2. 站点权限按需申请；
3. 面板查询必须绑定当前 `tabId` 或明确选择的 imported Session；
4. content script 不接收来自扩展的敏感历史数据；
5. 禁止通过页面消息触发任意 URL 请求、打开标签页或执行脚本；
6. `chrome.storage.local` 的敏感设置访问级别限制在可信扩展上下文；
7. 不把扩展内部资源无必要地声明为 web accessible。

### 4.3 内容安全策略

操作：

1. 所有执行代码随扩展打包；
2. 禁止远程脚本、`eval` 和 `new Function`；
3. 不使用内联可执行脚本；
4. 字体和图标随扩展打包；
5. 检查 Nuxt 与依赖的生产输出满足 Manifest V3 CSP；
6. Payload 中的 Markdown 如果需要渲染，必须经过明确的解析和净化流程。

### 4.4 脱敏

第一版至少支持按字段名隐藏：

- `authorization`；
- `cookie` / `set-cookie`；
- `apiKey` / `api_key`；
- `accessToken` / `refreshToken`；
- 用户配置的自定义字段。

脱敏应尽量在 SDK 侧先执行，扩展侧再次保护。导出文件默认继承当前脱敏设置，并在导出前让用户看到结果范围。

## 5. 综合验收步骤

1. 运行 1K、10K、50K 固定数据集并记录基准；
2. 运行持续事件流，检查事件数量、内存趋势和 dropped count；
3. 打开大 Payload 事件，只有详情面板加载完整内容；
4. 输入脚本、HTML、恶意 URL 和深层 JSON，确认不会执行或触发高权限动作；
5. 未授权站点无法建立采集链路；
6. 从标签页 A 的面板不能读取标签页 B 的实时数据；
7. 脱敏后的导出文件不包含设定字段的明文；
8. 扩展生产包在 CSP 检查下无远程代码；
9. 瀑布图与关系导航在所有协议 Fixtures 上结果正确；
10. 性能结果和未达标项记录在验收报告中。

## 6. 完成标准

- Timing、关联导航和导入导出可用于实际排障；
- 10K 事件规模达到初始性能目标；
- 大数据或限流场景不会静默丢失；
- 权限、消息、存储和渲染边界完成安全检查；
- 已知性能限制和最大推荐数据量有文档记录。
